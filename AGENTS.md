# Project instructions

## Current authorization

Set up and maintain this GitHub repository's documentation and project organization.
**Do not create, upload, or implement game code unless the owner explicitly authorizes that work.**
No engine has been approved. A local experiment does not establish a project decision.

## Read first

1. README.md
2. docs/DESIGN_BRIEF.md
3. docs/TECHNICAL_BASELINE.md
4. docs/FIRST_MILESTONE.md
5. docs/STATUS.md

## Preserve the game

- First-person gunner views on separate devices.
- Classic reticle aiming and limited arena scrolling.
- No conventional FPS locomotion, third-person mech controls, side-scrolling characters, or shared-screen substitutions.
- Design for 1–4 players, initially proving two-player networked combat.
- Preserve the pixel-art direction, distinct bosses, component destruction, independent weapons, phases, and shared damage.

## Working rules

- Inspect actual files before claiming an engine, architecture, asset inventory, or working feature exists.
- Preserve working systems and documented decisions. Flag contradictions before changing direction.
- Distinguish proposals, drafts, implementations, and verified results.
- Never call a system working without recording what was tested and where.
- Challenge unnecessary complexity; prefer the smallest useful deliverable without silently reducing the intended game.
- After two substantially identical failures, diagnose the cause and change the method.
- End substantive work with what changed, what was verified, and what remains unfinished.
- Keep communication direct and concise. Do not substitute planning volume for completed work.
- Avoid committing credentials, generated engine caches, or assets with unknown provenance.
